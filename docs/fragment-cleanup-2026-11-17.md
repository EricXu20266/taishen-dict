## 1. 第一阶段：语料跟随度分析（只读）

脚本：`tools/analyze_fragments.py`（新增）

口径：对每个 2~4 字、词频 < 3600 的词条，在 `tmp/corpus_50k_full`（76.8M 字，4 片）里统计

- `total_occ`：总出现次数
- `alone_occ`：前后都不是汉字的次数（真正独立成词）
- `follow_char/count` 与 `precede_char/count`：最强前后邻字

判定：`ratio > 0.9` 且绝对证据 ≥ 3 → prefix/suffix 碎片；独立占比 > 20% → standalone。

```
候选: 348,369 词（freq < 3600，2~4 字）
判定分布: {insufficient: 194,689, standalone: 147,238,
           prefix_frag: 3,809, suffix_frag: 2,633}
语料: 4 文件 76.8M 字，耗时 115s
```

产物：`tmp/fragments_candidates.tsv`（348,369 行）

碎片词频分布（6442 条）：

| freq 区间 | prefix | suffix |
|---|---|---|
| ≤1500 | 3704 | 2548 |
| 1501-2000 | 84 | 55 |
| 2001-2500 | 19 | 28 |
| 2501-3000 | 2 | 2 |

97% 的碎片词频在 1500 以下。在 `curate/common_dict.txt`（2431 词）里命中 **0 条**。

## 2. 第二阶段：语义复核

语料跟随度判不了「语义是否自足」——例如「电池板」「细查」「依阿华」在维基里也几乎总跟特定字，
但它们本身是完整词。所以第二阶段按语义再筛一遍。

口径调整（关键）：只处理 **occ ≥ 10、跟随率 ≥ 0.97、≥ 3 字** 的子集（1145 条），理由：

- `occ < 10` 证据太弱，降权收益也小
- 2 字词误判率最高（完整词多、候选竞争最直接），本轮一律不动
- `ratio ≥ 0.97` 把「中国→人（0.66）」这类高频词的语料偏置排除

保留规则：能独立成句成分或独立指称 → 保留；需要首字/尾字才成词 → 碎片。

保留清单：`tmp/fragments_keep.txt`（48 条），样例：

```
世界大战 百分点 百无一用 街道办 有限责任 可支配 货币基金 国际刑警
甲等医院 联欢晚会 配套改革 英国哲学 自治同盟 数据链 久经考验 额定电流
```

## 3. 第三阶段：抽检

对第一阶段（未做语义筛选前）随机抽 50 条人工核对，**准确率 84%**（8 条误判），低于 90% 门限。

8 条误判全部是「本身是完整词」：电池板、四氟乙烯、依阿华、神经科、商务平台、细查、谐振动、赔礼。
误判集中在 2 字与 3 字的完整名词/动词——这正是第 2 阶段把口径收紧到「≥3 字 + ratio ≥0.97 + 语义复核」的原因。

收紧后的子集没有再做 50 条抽检（样本经语义逐条过），如实记录：**本轮的准确率是「语义复核后」的，
不是「语料判定」的。**

## 5. 必须回答的问题：搭配表碎片率降了多少

**降幅为 0。** 原因是降权不改变分词：

`build_context_prior.py` 的 `load_vocab` 只按词长取词表、不看词频。碎片降到 1 仍在词表里，
正向最大匹配照样切出它们。实测重跑 385,983 对**逐条相同**。

于是试了第二层：给统计侧加分词排除（`--exclude-words`，新增参数）。四个方案对着同一批 120 例实测：

| 方案 | 搭配对数 | 档位6 | 120例提升 |
|---|---|---|---|
| 基线（现行线上） | 385,983 | 9,232 | **95** |
| 剔除 6442 碎片 | 384,439 | 9,311 | 91 |
| 剔除碎片＋长词内部切分保留 | 384,574 | 9,289 | 92 |
| 仅分词窗口放宽到 8 字 | 383,286 | 8,986 | 93 |

剔碎片后碎片对确实从 3556 对（0.92%）降到 **0**，但掉的 3-4 例全是这类：

```
北丐洪 + qigong → 七公      （北丐洪七公：5 字，词库无完整词）
恨不相逢 + weijia → 未嫁    （恨不相逢未嫁时：7 字，词库无）
国民生产 + zongzhi → 总值   （国民生产总值：7 字在库，但超过 4 字分词窗口）
```

根因：这些长词要么不在词库、要么超过分词窗口，碎片是它们唯一的切分入口。删了碎片，整段切不出来。

**结论**：统计侧剔除不通过 handoff 验收标准（≥95），已回退，`output/bigram.db` 保持 385,983 对不变。
`--exclude-words` 参数保留在工具里（默认关闭），供将来补完长词后重试。

## 7. 遗留与下一步

1. **长词覆盖率是真正的瓶颈**。`马尔马拉海`、`楚考烈王`、`国民生产总值`（7 字超窗口）、
   `北丐洪七公`、`恨不相逢未嫁时` 这类词不在词库或超出分词窗口，才让碎片成为唯一入口。
   建议下一轮做「碎片 → 补长词」：用碎片的高频跟随字在语料里还原完整词形，达标者入库。
2. **5273 条未处理碎片**：2 字碎片（误判率高）与 `occ < 10`（收益小）本轮未动。
   要处理必须先解决「完整词判别」，不能靠语料跟随度。
3. **分词窗口 4 字** 限制了 5 字以上长词的统计。放宽到 8 单独测过，120 例从 95 掉到 93，
   不采用；但与「补长词」一起做可能有不同结果。
4. 碎片清单可复用于「候选排序降权」之外的场景（如词库质量巡检）。
